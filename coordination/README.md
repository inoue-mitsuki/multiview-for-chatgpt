# 統合管理ルール

- タスクID: `<種別>-<3桁連番>`。最初のタスクは `PLAN-001`。
- 管理場所: `tasks/<ID>/task.md` が親タスク、同階層の役割名ファイルが作業指示、`reports/<ID>/` が役割別報告と統合報告。
- 役割: 必要な範囲で `researcher`、`dev`、`tester`、`reviewer` を使う。統合管理が最終判断する。
- 権限: 調査・試験・レビューは成果物を変更しない。実装の変更範囲は作業指示で限定する。
- 並列化: 独立した読み取り作業のみ並列化できる。同一ファイルの同時編集は禁止。
- 状態: 未着手、作業中、報告済み、確認中、完了、条件付き完了、差戻し、保留、中止。
- 完了判定: 統合管理が成果物、差分、検証結果を直接確認し、`integration.md` に記録する。
- 競合時: 変更を停止し、既存の差分を確認して担当を再指定する。
- 差戻し時: 該当作業指示を更新し、再確認する。
- 引継ぎ時: `handoffs/` に目的、状態、未解決事項、次作業を保存する。
