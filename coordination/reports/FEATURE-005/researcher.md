## 実施内容・確認した事実

- `extension/content.js` は、`document.documentElement` の末尾へ固定配置の分割ホストを追加し、ホストの `z-index` を `2147483647` に設定する。ホストはサイドバーの右端から画面右端までを覆う。標準メニューがこの領域へ展開されると、ホストより下に描画されて見えない可能性が高い。ただし、ChatGPTの実際のメニューDOMとスタッキングコンテキストは未確認。
- 会話URLの既存検証関数は `https://chatgpt.com/c/<id>` と `https://chatgpt.com/g/<id>/c/<id>` のみを許可する。`extension/background.js` の右クリック割当は `info.linkUrl` を利用し、`extension/content.js` の `assignConversation` は指定画面のiframeだけを更新する。
- Braveの `https://chatgpt.com/` タブはブラウザ一覧から確認できたが、`cua.getTab` は「Tab ... is already part of browser session ...」を返してバインドできなかった。従って標準メニューの実画面、DOM、具体的な属性は確認できていない。会話内容は読んでいない。

## 実装方針（推測を含む）

1. メニューの三点リーダーボタンを押す直前の `pointerdown` / `click` をトップページで捕捉し、起点の会話行にある `a[href]` を探して既存の会話URL検証関数を通す。DOM変更耐性のため、固定のクラス名やメニュー項目の日本語ラベルに依存しない。`event.composedPath()` からボタン周辺の行へたどり、行にある会話リンクを1つだけ特定できた時だけ対象URLとして保持する。通常会話とプロジェクト内会話の両方を上記URL形式で扱う。候補が複数または0なら割当項目を追加しない。
2. `MutationObserver` で開いた標準メニューを検出し、そのメニュー内に拡張側の「画面1～4で開く」項目を追加する。標準項目は移動・削除しない。メニューが閉じたら対象URLの一時情報を破棄する。重複挿入やChatGPTの再描画に備えて、項目に拡張固有の属性を付けて冪等に扱う。
3. メニューの実DOMと親スタッキングコンテキストを実機で確認し、標準メニューをホストより前面へ描画できるようにする。単に `z-index: 2147483647` をメニューへ設定しても、親のスタッキングコンテキストが低ければ効かない。まずホストの過大な `z-index` を下げ、必要な場合は実際のメニューポータルの祖先を局所的に前面へ出す。ホストをメインコンテンツのレイアウト内へ置く方法も検討できる。`pointer-events: none` だけでは視覚的な隠れを解消しない。
4. 項目選択時は保持したURLを再検証し、既存の `assignConversation` を呼ぶ。iframe内のメニューにはトップページのcontent scriptから手を加えられないため、まず標準サイドバー（トップページ）を対象にする。
