## 実施内容・確認したファイル
`extension/content.js`、`extension/background.js`、`extension/manifest.json` を読んだ。既存版は最上位ページ全体を shadow DOM の固定レイヤーで覆い、4つの iframe に同じ URL を設定する。ユーザー画像では同一ウィンドウの2×2表示と各 iframe 内の重複サイドバーが見える。

## 実装方針
1. 最上位の ChatGPT ページを維持し、標準サイドバーが占める左幅だけ固定レイヤーを空け、残りを拡張のワークスペースにする。左側は元ページのサイドバーそのものなので、既存のスクロールやリンク操作を原則維持できる。幅は `nav` 等の候補要素の実測矩形から求め、ウィンドウのリサイズやサイドバー開閉に追従する。ChatGPT の現行 DOM はこの調査で直接検証していないため、セレクタに依存する検出にはフォールバック幅を用意する。
2. ワークスペースの操作バーに 2/3/4 ボタンと終了ボタンを置く。ペインは一定の個数だけ作成し、選択数に応じた CSS grid へ切り替える。個別 iframe 参照を保持して、ドロップ先の `src` のみ変更する。
3. 最上位ページで `dragstart` を capture し、ドラッグ開始位置から近い `a[href]` の URL を読む。標準サイドバー内にある会話リンクかを確認し、`https://chatgpt.com/c/<conversation-id>` のような明確な会話パスだけ受理する。URL オブジェクトで origin、pathname、認証情報、不要なクエリやハッシュを確認する。既存の `dataTransfer` を消去せず、独自 MIME 型または `text/uri-list` に正規化URLを追加する。`dragover` と `drop` はペイン上だけ `preventDefault` し、受け取った文字列を再検証してから対象 iframe を更新する。
4. iframe 側は ChatGPT と同一 origin であれば、読み込み後に DOM にアクセスして重複サイドバーを隠す CSS を挿入できる。ただし ChatGPT がクライアント側で DOM を再生成する可能性があるため、専用の iframe 用 content script を全フレーム対象にし、`window.top !== window` のときだけ限定的 CSS を適用する案が安定する。非同一 origin のフレームには作用させず、ChatGPT ドメインの権限だけを使う。セレクタは実機で検証する必要がある。サイドバー幅だけ iframe を画面外へずらす方式は本文レイアウトも切れるため最終手段。

## 確認・試験結果
静的なコード調査のみ。現行 ChatGPT の DOM 構造、標準リンクのネイティブ dragstart、iframe 内での CSS 適用は未検証。ユーザー画像から4画面の表示は確認できるが、ドラッグ・ドロップ操作は確認できない。

## 発見した問題・未解決事項
- 現在の全画面レイヤーは標準サイドバーを隠す。レイアウト変更が必要。
- 現在の manifest と background は任意 HTTP(S) URL を許可しているため ChatGPT 専用へ戻す必要がある。
- ChatGPT の内部 DOM、サイドバー幅、リンク形式が変更されると検出や CSS が壊れる。固定セレクタへの依存を小さくし、判別不能時は安全に失敗させるべき。
- 会話リンクでない URL、外部 URL、`javascript:` 等をドロップしても iframe を変更しない。

## 推測・仮定
ChatGPT の標準サイドバー会話リンクが通常の `a[href]` であり、会話 URL は `/c/` 配下であると仮定。実機確認までは確定しない。

## 統合管理に判断を求める事項
会話リンク検出に失敗した場合の操作案として、サイドバー右クリックのリンクコピー後にペインへ貼り付ける補助導線を設けると実用性が上がるが、今回の必須仕様外のため実装要否は統合管理で判断。

## 次工程への引継ぎ
実装担当には、親ページサイドバー保持、ペイン単位のURL差し替え、限定 URL 検証、iframe内サイドバー非表示を段階的に実装してもらう。実機では2/3/4切替、D&Dで指定ペインだけ変わること、サイドバーのスクロール・通常クリック、終了復帰を試験する。
