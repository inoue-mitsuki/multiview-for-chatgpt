# 実装後の最低限の回帰テスト

## 毎回の実行順序
1. 下記の自動チェックを実行する。
2. Braveで必須ケースB01〜B10を確認する。変更した機能に関係する追加ケースE01〜E06も確認する。
3. RESULT-TEMPLATE.mdを使い、タスクのreports内に結果を残す。
4. 失敗は修正して再試験。実機未実施なら「自動成功・実機未確認」と報告し、全体成功にしない。

```powershell
& './extension/tests/run-tests.ps1'
```
プロジェクトルートで実行。Node.jsが必要。構文、manifest形式と参照先、全*.test.jsを確認。失敗時は停止する。

## 証明できる範囲
既存content-state.test.jsはDOM mockでメニュー注入、画面割当、番号、重複排除、配置、永続復元を確認する。実ChatGPTのDOM、CSSの重なり、Cookie/プロフィール、実際のネットワーク回数は証明しない。三点メニューとsidebarの見た目はBraveで必須確認。

## 実機の前提
- 拡張を再読み込みし、対象ChatGPTタブも更新する。版はmanifestと診断で一致を確認。
- 既存の通常会話A/B/CとプロジェクトP内の会話PA/PBを使用。テスト用チャットで行い、既存入力は送信または手元へ退避。
- 最初に現状の配置・URLを記録。保存データを削除せず、試験後に元へ戻す。
- 「空」＝案内と新しいチャットボタンがあり、会話を読み込んでいない状態。

| ID | 手順 | 期待結果 |
|---|---|---|

## 失敗時の記録
版・ケースID・直前の配置・クリック先・期待と実結果・スクリーンショットを記録。三点消失では会話行buttonとメニューのouterHTMLも取得し、mockと実DOMの差を調査する。実チャット名や本文・個人情報は必要以上に記録しない。
